# تشغيل Firebase والحسابات والغرف على Spark

## الحالة الحالية

- محول Firebase Authentication منفذ: إنشاء حساب، دخول، خروج، ضيف Anonymous، استعادة كلمة المرور، واستعادة الجلسة.
- ملف اللاعب يحفظ عبر Realtime Database ويقرأ عند الدخول من جهاز آخر. صفحة الدخول تعرض الاسم وآخر عشر نتائج أونلاين بعد الربط.
- خادم الغرف المنفصل منفذ؛ يستخدم محرك قواعد الموقع نفسه، ولا يقبل النقاط أو الحركة أو الفوز من المتصفح.
- الاختبار الحالي محلي صريح: `onlineMode: 'local'`، خادم Node على 5700، بيانات الغرف في ذاكرته، وهوية اختبار منفصلة لكل جلسة. ليست هذه حسابات Firebase ولا تُرفع نتائجها إلى الحسابات.
- المسار الحقيقي يستخدم Firebase Admin للتحقق من الهوية وحفظ الغرف ونتائج الأونلاين والأداء حسب الموضوع. يحتاج مفتاح الويب واعتماد الخادم وتطبيق القواعد للاختبار الفعلي. لم يُختبر الاتصال الحقيقي أو ينشر بعد.
- الأسئلة في الأونلاين تأتي حاليًا من بنك الخطة البديلة الموجود على الخادم، دون كشف الإجابات الصحيحة للمتصفح. دمج AI بالأونلاين مؤجل بطلب صاحبة المشروع. تقييم «حلل» تجريبي بكلمات مفتاحية؛ ليس تقييمًا دلاليًا من AI.
- نتائج الفردي واللعب على جهاز واحد تبقى محلية حاليًا؛ لا يرسل المتصفح أرصدتها إلى سجل الحساب كأنها نتائج موثوقة. لا توجد خوارزمية مستوى نهائية، ولا تنسب نتائج ضيوف الجهاز المشترك إلى المضيف.

## 1. التجربة الآن دون مفاتيح

من مجلد المشروع الذي يحتوي `Start-Madaar-Online.ps1`:

```powershell
node madaar_web/server/online/server.cjs
```

أو شغّل `Start-Madaar-Online.ps1` ليعمل الخادم دون نافذة إضافية. رابط الفحص:
`http://127.0.0.1:5700/api/online/health`، يجب أن يعرض `backend: local`.

افتح الموقع على Live Server كما سابقًا. لتجربة مسار الإعداد دون AI اختر الخطة البديلة من زاوية «كيف ألعب»، ثم افتح الإعداد، واختر الموضوع والنمط «تنافسي عن بُعد». في الغرفة أدخل اسمك ولونك وعدد اللاعبين، واضغط «إنشاء غرفة». افتح الموقع في نافذة خاصة أو متصفح آخر، واختر الغرفة نفسها بإدخال رقمها المكون من ستة أرقام. يبدأ المضيف بعد اكتمال العدد المختار. لا تستخدم حساب الاختبار نفسه لأكثر من مقعد؛ كل جلسة متصفح تمثل لاعبًا.

الانسحاب يغادر به صاحبه فقط. تستمر الغرفة ما دام فيها لاعبان أو أكثر، وتتوقف عند بقاء لاعب واحد وتعرض خيار الفردي. تحديث الصفحة يستعيد المقعد في جلسة المتصفح نفسها. فشل الشبكة يمنع إرسال الإجابات، ويُعاد جلب الحالة عند عودة الاتصال. إغلاق المتصفح وحده لا يعد انسحابًا؛ يجب استخدام الزر. سياسة مهلة الغياب وطرد المنقطع لم تُعتمد بعد.

إعادة تشغيل خادم `local` تمسح غرف الاختبار. لإنشاء جلسة اختبار جديدة بعد ذلك، امسح `madaarOnlineSeat` و`madaarOnlineLocalToken` من Session Storage. حسابات Firebase لا تتأثر بذلك.

## 2. مكان apiKey لاحقًا

الملف التنفيذي الوحيد لإعدادات الويب هو:

`madaar_web/firebase-config.js`

ضع مفتاح **Web API Key** فقط في:

```js
apiKey: 'PASTE_FIREBASE_WEB_API_KEY_HERE'
```

لا تحتاج إلى تعديل ملف Markdown القديم؛ هو مرجع فقط. لا تضع Service Account أو مفتاح AI في هذا الملف. معرفات تطبيق Firebase ورابط RTDB عامة، والخصوصية تعتمد على Authentication وقواعد الصلاحيات.

في Firebase Console → Authentication → Sign-in method فعّل **Email/Password** و**Anonymous**. وفي Settings → Authorized domains تحقق من إضافة `localhost` و`127.0.0.1` ونطاق الاستضافة المستخدم. تبقى كتابة كلمات المرور وإدارتها لدى Firebase Auth؛ لا يخزن الموقع كلمات مرور في Local Storage أو RTDB.

## 3. صلاحيات قاعدة البيانات

الملف الجاهز:

`madaar_web/integration/firebase/database.rules.json`

انسخ محتواه إلى Firebase Console → Realtime Database → Rules ثم Publish، أو انشره باستخدام CLI الموضح أدناه. القواعد تمنع القراءة العامة، وتسمح لصاحب الحساب بقراءة بياناته وتعديل ملفه المحدد فقط. النتائج والتقدم والغرف الخاصة يكتبها الخادم عبر Admin SDK وحده. لا تستخدم قواعد تسمح للجميع بالقراءة والكتابة.

هيكل البيانات:

- `users/{uid}/profile`: الاسم، اللغة، الفئة العمرية، خيار المتعلم الجديد.
- `users/{uid}/results/{sessionId}`: النقاط، الفوز، المركز مع التعادل، التاريخ ومصدر الأسئلة.
- `users/{uid}/progress/{topicHash}/{sessionId}`: محاولات الموضوع ودرجات البطاقات؛ لا يصنف اللاعب إلى مستوى مخترع.
- `onlinePrivate/{roomCode}`: العضوية وحالة اللعبة والأسئلة ومعيار الإجابة ومواعيدها والأحداث. لا يقرأه المتصفح مباشرة؛ الخادم يعيد العرض المسموح لأعضاء الغرفة فقط.

النتيجة النهائية تثبت داخل سجل الغرفة، ثم يُنسخ سجل الحساب بكتابة متعددة المسارات قابلة للإعادة بالمعرف نفسه. إذا فشل النسخ، تعيد قراءة الغرفة المحاولة، فلا يعاد احتساب الدور أو النقاط.

## 4. اعتماد الخادم الحقيقي — منفصل عن apiKey

المفتاح العام للويب لا يكفي لصلاحيات الخادم. من Firebase Console → Project settings → Service accounts يمكن إنشاء مفتاح اعتماد للخادم. احتفظ بملف JSON خارج مجلد الموقع المنشور، مثل `.secrets/firebase-service-account.json` في جذر مساحة العمل؛ هذا المسار مستثنى من Git. لا تشاركه في المحادثة أو تنشره على Hosting.

انسخ:

`madaar_web/server/online/.env.example`

إلى:

`madaar_web/server/online/.env`

املأ/غيّر:

```dotenv
ONLINE_BACKEND=firebase
GOOGLE_APPLICATION_CREDENTIALS=C:/absolute/private/path/firebase-service-account.json
FIREBASE_PROJECT_ID=madaar-web-game
FIREBASE_DATABASE_URL=https://madaar-web-game-default-rtdb.asia-southeast1.firebasedatabase.app
```

الاعتماد لا ينشئ رسوم Blaze؛ الخادم يعمل خارج Cloud Functions. يمكن استخدام هوية تشغيل معتمدة بدل ملف خاص عند اختيار الاستضافة. بيانات الاعتماد تحفظ في بيئة الخادم فقط.

ثبّت اعتماد الخادم وشغّله:

```powershell
cd madaar_web/server/online
npm ci --no-audit --no-fund
npm start
```

ثم غيّر في `firebase-config.js`:

```js
onlineMode: 'firebase'
```

أعد تشغيل خادم الغرف بعد تغيير `.env`. تأكد أن فحص health يعرض `backend: firebase` و`verifiedIdentity: true`. لا يستبدل المسار الحقيقي نفسه بالمحاكاة عند فشل الاتصال. تحتاج إعدادات الاعتماد والقواعد إلى تجربة فعلية قبل تأكيد الجاهزية.

## 5. الاستضافة على Spark

أُعد `firebase.json` و`.firebaserc` في جذر مساحة العمل. ينشر Hosting صفحات الموقع وأصوله، ويستثني مجلدات الخادم والتكاملات والمواصفات والاختبارات والشاشات المرجعية. رابط `/` يحول إلى `Main.html`.

بعد تثبيت Firebase CLI وتسجيل الدخول إلى حسابك:

يمكن تثبيت الأداة بأمر `npm install -g firebase-tools` وفق [توثيق Firebase](https://firebase.google.com/docs/cli). لم نثبت CLI أو نسجل الدخول نيابةً عنك في هذه المرحلة.

```powershell
firebase login
firebase use madaar-web-game
firebase deploy --only database,hosting
```

لم يُنفذ تسجيل دخول CLI أو نشر شيء في حسابك بعد. قبل النشر الكامل حدد استضافة خادم الغرف المنفصل؛ هذا قرار لاحق. يجب أن يكون عنوانه HTTPS، وأن تضيف نطاق الموقع إلى `ALLOWED_ORIGINS` في بيئته، وتضع العنوان في `onlineApiBaseUrl` في `firebase-config.js`.

**لا يمكن لعب الأونلاين من أجهزة أخرى عبر العنوان `127.0.0.1`**؛ يشير إلى جهاز اللاعب نفسه. Hosting وحده ينشر الواجهة ولا يشغّل خادم Node. لا يلزم تغيير خطة Firebase إلى Blaze، لكن الخادم المنفصل يحتاج عنوانًا مشتركًا يمكن الوصول إليه. لم يُختَر مزود استضافته بعد.

## ملفات التنفيذ والاختبار

- `firebase-config.js`: إعداد واحد للويب والحسابات وعنوان الغرف.
- `firebase-service.js`: SDK والتوثيق وحفظ/قراءة ملف الحساب.
- `session-service.js`: فصل الجلسة عن أرصدة اللعبة، ومسح بيانات الجولة والخروج.
- `login-controller.js` و`account-view.js`: الواجهة الحالية للحساب واستعادة كلمة المرور والنتائج.
- `online-service.js`: اتصال مصرح به بالخادم، مقعد الغرفة، وجلب التحديثات كل ثانية دون إعادة تحميل الصفحة.
- `room-controller.js` و`online-play.js`: الغرفة والرقعة مع صاحب الدور والمشاركين في التحدي.
- `server/online/rooms.cjs`: الحالة والصلاحيات ومنع تكرار الأحداث.
- `server/online/rules.cjs`: تشغيل المحرك الحالي وبنك التدريب على الخادم.
- `server/online/server.cjs`: HTTP، Firebase Admin، معاملات RTDB وحفظ النتائج.

التحقق المحلي:

```powershell
node --test madaar_web/server/online/test.cjs
node madaar_web/tests/firebase-service.cjs
node madaar_web/tests/rules.cjs
node madaar_web/tests/colored-trial.cjs
```

اختبار المتصفح المنفذ على Live Server موجود في `output/check-online-ui.cjs`: ثلاث جلسات معزولة، سؤال موحد، منع المتفرج من الإجابة، ثبات الإدخال أثناء التحديث، النقاط واستعادة المقعد والانسحاب وعرض الهاتف. هذا اختبار خادم `local` وليس إثباتًا لاتصال Firebase الحقيقي.

ويختبر `output/check-online-cells.cjs` الأنواع السبعة الجماعية بين جلستين، مع خادم اختبار معزول. اجتازت بطاقات المصباح والمضاعفة والأمان والمعرفة والتحدي والمنافسة والتعاون الاختبار. اختبار `tests/firebase-service.cjs` يستخدم SDK بديلًا للتحقق من اتفاق المحول؛ لا يغني عن اختبار Firebase الحقيقي أو اختبار الصلاحيات على محاكي Firebase بعد توفير أدواته.
