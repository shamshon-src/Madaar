# إعداد خدمة الذكاء الاصطناعي لمدار خطوة بخطوة

## الهدف والحالة الحالية

الخيار المقترح هو نموذج عبر API خارجي، لتوليد أسئلة من محتوى موثق وتقييم الإجابات النصية حسب المعنى. هذا أسهل في التجهيز والنشر من استضافة نموذج محلي، لكنه يحتاج إنترنت وفوترة استخدام. جودة التصحيح تحتاج اختبارًا قبل الاعتماد عليها.

**هذا الملف دليل إعداد، وليس تنفيذًا للربط الجديد.** الخدمة الحالية تستخدم أسئلة جاهزة وتقييمًا بالكلمات المفتاحية. وضع المفتاح وحده لن يحولها إلى خدمة توليد أو تقييم دلالي.

## 1. تجهيز حساب API

1. افتح https://platform.openai.com/ وسجل الدخول.
2. أنشئ مشروعًا خاصًا بمدار أو اختر مشروعك الموجود.
3. افتح إعدادات الفوترة والاستخدام وجهز وسيلة الدفع أو الرصيد المطلوب بحسب حسابك. لا تفترض أن اشتراك ChatGPT يغطي استخدام API.
4. راجع إعدادات الميزانية والتنبيهات. لا تعتمد على تنبيه الميزانية وحده كحد قاطع للاستهلاك؛ سنضيف قيودًا داخل التطبيق.
5. افتح https://platform.openai.com/api-keys وأنشئ مفتاحًا للمشروع.
6. انسخ المفتاح مباشرة إلى الملف الخاص الموضح في الخطوة التالية. لا ترسله في المحادثة أو صورة شاشة.

## 2. وضع المفتاح في مكانه

من جذر مساحة العمل الحالية، أنشئ هذا الملف إذا لم يكن موجودًا:

```text
madaar_web/server/.env
```

المسار الكامل على جهازك:

```text
C:\Users\sshan\Documents\AI hackathon\madaar_web\madaar_web\madaar_web\server\.env
```

هذا ملف خدمة AI. الملف المفتوح حاليًا `madaar_web/server/online/.env` مخصص لخدمة اللعب عبر الإنترنت؛ ضع مفتاح AI في الملف السابق.

أضف السطر التالي واستبدل النص التوضيحي بالمفتاح الحقيقي بنفسك:

```dotenv
OPENAI_API_KEY=ضع_المفتاح_الحقيقي_هنا
```

إذا كان الملف موجودًا، حافظ على إعداداته الأخرى وعدل سطر المفتاح أو أضفه مرة واحدة. احفظ الملف. لا تنسخ المفتاح إلى JavaScript أو HTML أو `service-config.js`.

## 3. إبلاغ المطور دون مشاركة السر

أرسل فقط:

> وضعت المفتاح في madaar_web/server/.env. جهز الربط دون فتح ملفات الأسرار أو طباعة قيمها.

لا تحتاج إلى إرسال محتوى الملف. سيحمّل برنامج الخادم المفتاح أثناء التشغيل؛ لا يحتاج المطور إلى رؤيته أو قراءته بأدوات الفحص. يجب استبعاد ملفات `.env` الفعلية من البحث والتقارير، وإخفاء بيانات المصادقة من الأخطاء والسجلات.

## 4. العمل البرمجي المطلوب بعد الإعداد

هذه خطوات ينفذها المطور، وليست أوامر مطلوبًا منك تشغيلها الآن:

1. تحميل إعدادات AI من `server/.env` بمسار صريح؛ التشغيل الحالي لا يحمّل هذا الملف لخدمة Python تلقائيًا.
2. إضافة محول API على الخادم واختيار نموذج متاح للحساب، قابل للتغيير عبر الإعدادات.
3. استرجاع المقاطع الموثقة أولًا، ثم تمريرها للنموذج لصياغة السؤال والخيارات ومعيار التصحيح. حفظ مفتاح الإجابة في الخادم.
4. تقييم إجابة «حلّل» بحسب عناصر معيار السؤال، مع نتيجة منظمة ودرجة ضمن الحدود وشرح للعناصر المتحققة والناقصة.
5. التحقق من صحة المخرجات والمراجع وحدود الدرجة قبل إرسالها لواجهة مدار. يبقى احتساب النقاط والحركة والفوز في محرك اللعبة.
6. إضافة مهلة اتصال وقيود استهلاك والتعامل الواضح مع فشل الخدمة؛ لا يتحول إلى المحاكاة بصمت.
7. اختبار إجابات صحيحة وخاطئة وصياغات مترادفة وإجابات خارج الموضوع ومحاولات تغيير التعليمات.
8. تجهيز مقاطع إنجليزية موثقة وترجمات معتمدة للنصوص الشرعية. المفتاح وحده لا يوفر هذه البيانات.

## 5. التشغيل والتحقق بعد اكتمال التعديل

من جذر مساحة العمل:

```powershell
.\Start-Madaar-AI.ps1
```

افتح فحص الخدمة:

```text
http://127.0.0.1:8001/api/ai/health
```

ثم افتح موقعك:

```text
http://127.0.0.1:5501/madaar_web/Setup.html
```

ابدأ لعبة جديدة وجرب «اعرف» و«استكشف» و«حلّل». نجاح فحص الصحة وحده لا يثبت نجاح استدعاء النموذج؛ يلزم نجاح طلب توليد وطلب تقييم فعليين. في النسخة الحالية `modelConnected: false` يعكس غياب النموذج، وليس خطأ في المفتاح الذي أضفته.

## 6. الرفع والنشر

ملفات `.env` مدرجة في `.gitignore`. عند رفع ZIP أو المجلد يدويًا استبعدها بنفسك؛ `.gitignore` لا يحمي الرفع اليدوي. عند النشر، ضع `OPENAI_API_KEY` في إعدادات أسرار منصة استضافة الـbackend. عنوان `127.0.0.1` مخصص للتجربة المحلية؛ الموقع المنشور يحتاج عنوان backend منشورًا وإعدادات السماح باتصال الواجهة.

## نتيجة فحص مكتبات البحث في المشروع

الفحص شمل الكود وملفات الاعتماديات والتوثيق، واستبعد ملفات الأسرار والاعتماديات المنزلة والكاش. وجود مكتبة في `requirements.txt` لا يثبت أنها مثبتة أو مستخدمة أثناء التشغيل.

| الاسم | النتيجة | الاستخدام الحالي |
| --- | --- | --- |
| `sentence-transformers` | لم يُعثر عليه في ملفات المشروع المفحوصة | لا يوجد تنفيذ يستخدمه |
| `FAISS` | لم يُعثر عليه | لا يوجد فهرس FAISS في التنفيذ المفحوص |
| `Chroma` / `chromadb` | لم يُعثر عليه | لا يوجد تنفيذ يستخدمه |
| `embedding` / `embeddings` | موجود في الإعدادات والتوثيق وSQL | لا توجد عملية توليد تضمينات في كود الخدمة الحالي |
| `vector` / `pgvector` | موجود | مخطط SQL وقائمة اعتماديات وإعداد Docker؛ غير موصول بالبحث الحالي |
| `similarity` | لم يُعثر على الاسم | يوجد تعريف `vector_cosine_ops` في مخطط SQL، لكن لا توجد استعلامات تشابه متجهي منفذة في الخدمة |
| `retrieve` | موجود ومستخدم | استرجاع محلي بمطابقة الكلمات والموضوع والقسم |
| `top_k` | موجود ومستخدم | تحديد عدد النتائج بعد ترتيبها بالدرجات المحلية |

الملفات المهمة داخل `Madar_Final_Ministry_Ready/`:

- `backend/app/services/retrieval.py`: يقرأ JSON، ويعطي 12 درجة لتطابق الموضوع و5 للقسم، ويضيف عدد الكلمات المشتركة، ثم يعيد أول `top_k` نتائج معلمة `approved`. هذا بحث لفظي، وليس بحثًا دلاليًا بالتضمينات.
- `backend/app/api/rag.py`: مسار `/rag/search` يستدعي الدالة المحلية نفسها.
- `backend/app/core/config.py`: يحتوي اسم نموذج embeddings وعلم `use_vector_rag`، دون تنفيذ يفعلهما.
- `backend/requirements.txt`: يذكر `pgvector==0.3.6`.
- `supabase/schema.sql`: يعرف `embedding vector(1536)` وفهرس HNSW باستخدام `vector_cosine_ops`. وجود المخطط لا يعني أن قاعدة البيانات أُنشئت أو امتلأت ببيانات.
- `docker-compose.yml`: إعداد PostgreSQL مع pgvector؛ وجود الملف لا يعني أن الحاوية تعمل.

**الخلاصة التقنية:** توجد تجهيزات ومخطط لبحث متجهي، لكن البحث الذي يعمل الآن محلي ولفظي. لا يلزم FAISS أو Chroma لتطوير الربط؛ يمكن استخدام pgvector الموجود في تصميم المشروع لاحقًا. توليد الأسئلة والتقييم الدلالي يمكن ربطهما بالمقاطع المحلية أولًا، ثم تطوير الاسترجاع المتجهي.
